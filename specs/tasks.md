# Tarefas

As tarefas abaixo traduzem os requisitos de `specs/spec.md` e as decisões de `specs/plan.md` em entregas implementáveis. A implementação deve respeitar também a arquitetura, a qualidade e as convenções de `specs/constitution.md`.

| ID | Tarefa | Origem | Depende de | Concluída quando |
|---|---|---|---|---|
| T-01 | Criar a solução e os projetos da aplicação e dos testes | Plano, Constituição | — | A solução .NET 10 contém projetos para Api, Application, Domain, Infrastructure, testes Unit e Integration, com referências entre camadas coerentes com o plano; `dotnet build` compila a solução. |
| T-02 | Implementar o modelo e as regras de senha no domínio | RF01, RF03, RN01–RN04, RN09–RN10, Plano | T-01 | O domínio gera senhas com pelo menos 16 caracteres, ao menos um caractere de pontuação ASCII permitido, nenhum espaço ou caractere fora do conjunto ASCII especificado, e associa cada senha a um GUID próprio sem exigir conteúdo textual inédito. |
| T-03 | Cobrir as regras de domínio com testes unitários | RN01–RN04, RN09–RN10, RN12, CA01, CA08–CA10, CA12, Constituição | T-02 | Testes unitários verificam comprimento mínimo (incluindo exatamente 16), presença de pontuação, ausência de espaços, aceitação e rejeição dos conjuntos de caracteres e geração de identificadores próprios; todos passam. |
| T-04 | Definir contratos e serviço de aplicação para geração e consulta | RF01–RF07, RN04–RN07, Plano, Constituição | T-01, T-02 | A camada Application define os contratos de persistência e os DTOs necessários e implementa a orquestração de geração, armazenamento obrigatório antes do sucesso e consulta por GUID, sem regra de negócio nos endpoints. |
| T-05 | Implementar persistência SQLite com EF Core | RF02, RF06, RN05–RN08, RN11, Plano | T-04 | A Infrastructure configura EF Core e SQLite, persiste e consulta registros por GUID sem sobrescrever registros anteriores, e disponibiliza a implementação do contrato de repositório; falhas de gravação são propagadas ao serviço sem produzir sucesso falso. |
| T-06 | Implementar os endpoints Minimal API e respostas HTTP | RF01, RF03–RF07, Plano, Constituição | T-04, T-05 | `POST /passwords` retorna senha e GUID somente após persistência bem-sucedida; `GET /passwords/{id}` retorna o registro existente, 404 para GUID válido inexistente e 400 com ProblemDetails em entrada inválida ou ausente. Os endpoints delegam a lógica à Application. |
| T-07 | Configurar inicialização e injeção de dependências da API | Plano, Constituição | T-01, T-04, T-05, T-06 | A API registra serviço de aplicação, repositório e contexto SQLite, inicializa a aplicação sem configuração manual fora do projeto e pode ser executada localmente. |
| T-08 | Preparar infraestrutura de testes de integração | CA01–CA12, Constituição, Plano | T-01, T-07 | O projeto de integração inicia a API com dependências controláveis e persistência isolada por teste, permitindo verificar respostas HTTP e registros sem depender de dados compartilhados entre execuções. |
| T-09 | Testar os fluxos de sucesso dos endpoints | RF01–RF05, RN01–RN07, RN11–RN12, CA01–CA04, CA08, CA11–CA12, Constituição | T-08 | Testes de integração comprovam geração com senha conforme as regras, retorno de GUID válido, consulta que recupera exatamente a senha, disponibilidade após a geração e múltiplas gerações preservando os registros anteriores. |
| T-10 | Testar erros de entrada, ausência de registro e falha de persistência | RF05–RF07, CA05–CA07, Plano, Constituição | T-08 | Testes de integração comprovam 400 com ProblemDetails para GUID inválido e ausente, 404 para GUID válido inexistente e resposta sem senha/GUID nem confirmação de sucesso quando o armazenamento falha. |
| T-11 | Documentar execução, endpoints e limitações didáticas | RN08, Plano, Constituição | T-07, T-09, T-10 | A documentação do projeto descreve como executar a API e os testes, apresenta os endpoints e deixa explícito que senhas são armazenadas sem proteção e que a solução não é adequada para produção. |
